# Android file handoffs, Back and export sizing

These findings apply to the 0.12.7 Test app at `14df73926c6f7063a488f84e367268168e8e5444`. A condition such as activity destruction or a particular provider is stated explicitly. No such interruption was induced on the owner's phone in this audit.

## AND-01 · High conditional · Returning from the file picker after activity destruction can lose an export

In Regular start with an edited photo and choose Save PNG. Leave the Android destination picker open. The export recipe lives in Compose `remember`. Android may destroy the host activity while the picker is in front. On a fresh host the pending operation is null. Even if the Android result delivers a valid destination URI, Regular's callback only writes when both that URI and the in-memory request exist. A returned destination can receive no image and no recovery message. Android's result API explicitly requires the application to save the context needed to act on the result. [Regular pending state](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/main/java/com/greenezone/gzphotoeditor/ui/PhotoEditorScreen.kt#L134-L170) · [Result handler and launch](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/main/java/com/greenezone/gzphotoeditor/ui/PhotoEditorScreen.kt#L589-L614) · [Android Activity Result API](https://developer.android.com/training/basics/intents/result)

Collage and Pro likewise require a remembered pending snapshot. The video GIF path encodes a temporary GIF first, then awaits a deferred destination in a screen-owned coroutine. Killing that process loses the waiter. A hard kill can also bypass the cleanup that normally removes the staging file. Android may reclaim cache files under pressure. These are separate reasons a path to a temporary file alone cannot guarantee recovery. The timing of an interruption and what an individual provider leaves visible are unmeasured. [Collage](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/main/java/com/greenezone/gzphotoeditor/ui/CollageWorkspaceScreen.kt#L365-L384) · [Pro](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/main/java/com/greenezone/gzphotoeditor/ui/ProWorkspaceScreen.kt#L543-L559) · [GIF picker and write](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/main/java/com/greenezone/gzphotoeditor/ui/VideoGifScreen.kt#L254-L305) · [Cleanup](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/main/java/com/greenezone/gzphotoeditor/ui/VideoGifScreen.kt#L308-L334) · [Android cache guidance](https://developer.android.com/training/data-storage/app-specific#remove-cache-files)

**Suggested repair.** Give each export a stable operation ID bound to workspace, source identities, immutable recipe revision, format and current phase. Persist enough before opening the picker to restore the correct workspace and handle a redelivered result. Keep a small pointer in saved state and durable recipes in private storage. Bitmap buffers and complete histories are too large for saved-instance bundles. If a staged file was reclaimed, keep the edits and offer to regenerate. Only resume a commit whose destination and ownership are known. Handle cancellation and repeated delivery idempotently. A truthful retry path may be simpler than automatic recovery after an ambiguous write. Expire owned dead stages after reconciling live operations. Select the smallest design that passes the interruption cases across the existing workspaces. [Android saved state and persistent data](https://developer.android.com/topic/libraries/architecture/saving-states)

**Falsification test.** Use distinct A and B, a disposable destination and a provider or Activity Result seam that can delay returning the URI. First export A normally as a control. Recreate the host while choosing A's destination, then deliver success, cancellation and duplicate success in separate cases. Verify externally decoded pixels and the number of writes. Repeat with a backgrounded process killed while a separate picker remains foreground, restoring from Recents. Record the actual PID change. Activity recreation, screen rotation and force-stop have different semantics. Inject an error before destination open and after a partial write. A pre-open failure must preserve the previous bytes. A mid-write failure must give an honest recovery result. Existing staging already finishes encoding before opening the provider and continues an initiated copy. Keep those properties. Never delete an unknown existing provider document in cleanup. ## AND-02 · Medium · Regular can promise original dimensions while exporting fewer pixels

Regular's dialog says “Original edited image dimensions.” With an unedited 6000×4000 input and a reported 256 MiB memory class, the exact budget is 10,066,329 pixels. The decoder's square-root scaling and rounding request **3886×2591**. Original sizing returns this bitmap as-is. The guard is doing useful work; the dialog communicates a different result. This is the Regular downscaling case. The Pro chapter details a separate case where a small source instead grows. [Dialog](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/main/java/com/greenezone/gzphotoeditor/ui/EditorDialogs.kt#L81-L106) · [Budget and decode](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/main/java/com/greenezone/gzphotoeditor/editor/ImagePipeline.kt#L45-L76) · [Regular export](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/main/java/com/greenezone/gzphotoeditor/ui/PhotoEditorScreen.kt#L280-L310) · [Original sizing](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/main/java/com/greenezone/gzphotoeditor/editor/ImageExportWriter.kt#L15-L23)

**Suggested repair and test.** Use the same preflight calculation for the dimension readout and writer. Account for EXIF orientation, crop, rotation, preset, and memory class. Show the exact result in the existing dimension field if the full output cannot be produced. If full resolution is a product requirement, add a bounded tiled export path and pixel-compare it against a small reference, including blur edges and transforms. Simply increasing the heap limit would leave other devices exposed. Parameterize the 24 MP example at 128 and 256 MiB and the small-source example in Pro. Inspect the final PNG dimensions with an external reader, plus an asymmetric corner chart after a rotated crop. [Android ImageDecoder](https://developer.android.com/reference/android/graphics/ImageDecoder)

## Physical Back and document access · acceptance still open

- The test helper calls AndroidX's committed Back dispatcher directly. The manifest opts into platform dispatch and handles orientation changes in place. Those facts support committed application navigation. They do not measure either edge's physical gesture, cancellation before release, keyboard/picker precedence, or return to a process reclaimed while backgrounded. Test both edges in Regular, GIF and Pro, half-drag then release, rapid Back twice, a dirty tile, the keyboard, and the destination picker. Record each visible route before/after. A canceled gesture leaves the current draft and history intact. A committed gesture pops exactly one eligible context. [Dispatcher helper](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/androidTest/java/com/greenezone/gzphotoeditor/AndroidBackNavigationTest.kt#L146-L151) · [Manifest](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/main/AndroidManifest.xml#L8-L14) · [Android predictive Back guidance](https://developer.android.com/guide/navigation/custom-back/predictive-back-gesture)
- Regular catches a rejected persistable read grant and proceeds with the current import. Later project saves store the source URI. A named save can therefore outlive access to its media. A moved or deleted source is a separate case. Use a real local provider, a transient-only provider and a deliberately revoked grant. On cold reopen keep the recipe and offer a source-specific relink. Exercise the app's existing Pro replacement support. For a GIF draft demonstrate editable settings and timeline after process restart, distinct from reopening exported GIF bytes. [Grant handling](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/main/java/com/greenezone/gzphotoeditor/ui/PhotoEditorScreen.kt#L217-L240) · [Stored Regular reference](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/main/java/com/greenezone/gzphotoeditor/editor/ProjectStore.kt#L33-L45) · [Android document access](https://developer.android.com/training/data-storage/shared/documents-files) · [Photo picker persistence](https://developer.android.com/training/data-storage/shared/photo-picker)
- A literal URI comparison guards identical source/destination strings. Two references can have different identities from an app's perspective. Only a controlled provider test that returns two URIs for the same backing item could establish an alias overwrite here; this audit found no such phone observation. Include an alias-capable test double and an ordinary CreateDocument provider as controls. Preserve write-only provider support and show original checksums. Treat source aliasing as an investigation, separate from the confirmed, ordinary wrong-name project writes.
