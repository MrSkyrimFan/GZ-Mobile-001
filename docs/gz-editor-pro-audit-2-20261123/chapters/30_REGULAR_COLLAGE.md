# Regular and Collage — protect the user's pixels and work

Reviewed the app at `14df73926c6f7063a488f84e367268168e8e5444`. The cases below trace normal controls to their state changes or render/storage paths. They are source findings unless individually identified as emulator evidence or independent controls. Android instrumentation and physical-device execution of the new sequences are still pending. ## REG-01 · High · Flipping a photo can uncover material the user already covered

Put an opaque black bar over a small marker on the left side of a photo. Flip horizontally. The background photo mirrors, placing the marker on the right. The bar stays on the left. Regular export applies that same recipe again. A sensitive feature covered before the flip can be present in the exported file. In this case the source clearly shows the failure even with neutral color, no resizing, and an entirely opaque mark. The simple blur has different concealment semantics. ## REG-03 · High · Opening another photo or project can discard an unsaved draft

Apply a visible edit to photo A. **Open media** and pick B, or choose another named project. A successful decode installs B and resets Undo and the baseline. Regular already offers save/discard/keep for Back, but neither successful replacement passes through that decision. Canceling the picker or a failed decode before installation normally preserves A. In Collage, editing the current layout and opening another saved collage also replaces the document and clears its history. These paths are distinct from the Pro wrong-name overwrite. ## COL-01 · Medium · Moving a photo and undoing can select its neighbor

Undo restores A, B, C but clamps the existing selected slot to zero. **Edit selected** or **Replace** subsequently targets A. The same fixed-slot policy applies on Redo. A current highlight can show the new target, yet the editing sequence has lost the object the user moved. ## COL-03 · Medium · A missing tile can leave the previous collage on screen

Open intact A, then open named B whose image grant is revoked. B's saved JSON can load even though the image is unreadable. The successful name lookup replaces the current document with B. When its preview fails, the composable sets the missing index, switches to Photos and posts a notice. The previous bitmap stays in `preview`. It is drawn at the same time that taps and outlines use B's current layout. This depends on A having rendered in the same screen instance. A fresh empty screen has no prior bitmap to show. The suggested Replace action creates a new blank tile recipe, so using it as a relink for the same photograph also discards that tile's previous edits. The source expressly labels replacement as clearing adjustments. ## REG-05 · Medium · Text spacing splits an emoji into invalid character fragments

Add the caption `GO 😀!` with no grading or crop, then increase **Text → Spacing**. Positive spacing sends one Kotlin `Char` at a time to `Canvas.drawText`. The emoji's UTF-16 surrogate pair becomes two independent draw calls. Combining accents and joined emoji lose shaping context as well. The recipe can still contain the intended text. Glyph appearance on a given phone depends on its fonts. Also the wrap calculation measures the run without spacing while the draw operation increases its width. This is a specific defect that can coexist with a working Add text button and a passing simple caption export. ## Preserve the proven paths and mode boundaries

- The real Regular → Pro handoff tests a noncentral crop plus a Look, 16 visible probes, UI save, stored recipe, Back to the Regular draft and original file bytes. A new privacy-coordinate or crop fix should repeat that journey with an asymmetric cover. Also retain No, Cancel, and the Regular Undo baseline. [Cropped handoff regression](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/androidTest/java/com/greenezone/gzphotoeditor/AndroidBackNavigationTest.kt#L723-L809)
- Regular and embedded Collage tile editing omit mask authoring while rendering and storing old mask data. Maintain that property for old saves. Keep Regular Text and Blur & cover in their existing menus. [Legacy mask regressions](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/androidTest/java/com/greenezone/gzphotoeditor/AndroidRegularToolsTest.kt#L217-L279)
- Protect independent per-tile edits, PNG export, and missing-input errors throughout. For storage robustness, the Collage store has a rename-to-copy fallback on disk failure that can write over an existing destination in place. Treat this as a conditional fault-injection target, separate from the source-confirmed ordinary UI failures above. Inject a replacement failure with a last-known-good save, kill immediately before/after publication, and compare retained data before declaring recoverability. Android's AtomicFile and the existing Pro store offer specific implementation patterns; concurrent writes still need ordering.
