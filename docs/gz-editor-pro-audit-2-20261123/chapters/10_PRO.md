# Pro projects, live drawing and pixel geometry

The most important property of Pro is that reopening a named project restores the work the user intended to save. Two independent paths can violate that property. PRO-01 concerns the destination. PRO-05 concerns the contents of the file written there. Fixing one still leaves the other reproducible. The source references in this chapter are pinned to the app tree exercised by v0.12.7. The proposed Android cases describe work for Codex. The included host control demonstrates numeric boundaries only.

| ID | Priority | User-visible behavior | Evidence |
|---|---|---|---|
| PRO-01 | High, carried forward | A default Save after opening B can replace A | UI-to-store trace on pinned source |
| PRO-05 | High, new | A model-valid dense drawing can exceed its nested reader's limit while fitting the writer's limit | Writer/reader trace and executed Java numeric boundary control |
| PRO-03 | Medium, new | Direct Pro import of a very wide or tall image gives the guide, hit test and retouch tool a different aspect from the rendered image | Normal import trace and geometry control |
| PRO-04 | Medium, new | “Original edited image dimensions” can export a different size, even for an 80 × 80 edited photo | Dialog-to-export trace and sizing control |
| PRO-02 | Medium, carried forward | A held brush or eraser stops adding points after 500 samples | Input, validation, persistence and renderer traced |

## PRO-01 · Save destination survives the wrong project

**Reproduction.** Prepare two named projects with visually distinct layers, A and B. In the same Pro session save A, open B from File, edit B, then open Save. A is prefilled. Accepting the displayed default atomically replaces A with B's contents. The name is visible and can be edited. The issue is the wrong default and lack of protection when replacing a different project. Opening B swaps its document and reset baseline. The text field still reads the last typed name. The store normalizes whitespace before selecting a file, so a replacement check needs to compare the same canonical key that the writer uses. [Remembered text](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/main/java/com/greenezone/gzphotoeditor/ui/ProWorkspaceScreen.kt#L189-L194) · [Save and Open handlers](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/main/java/com/greenezone/gzphotoeditor/ui/ProWorkspaceScreen.kt#L1321-L1350) · [Key and atomic write](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/main/java/com/greenezone/gzphotoeditor/editor/ProStore.kt#L221-L265)

**Repair choices.** Give each working session an explicit save target or a clean unbound state. Initialize the existing name field from that state when the dialog opens. Bind it on successful open/save, restore it consistently across Undo of Open, and handle deliberate deletion of the bound name. Canceling a dialog or failing to write should keep the prior binding. A collision with a *different* existing project should name the destination and require an intentional replacement decision. An alternative that always starts an unbound save with an empty field also works if the user can still deliberately update an existing project. Keep atomic replacement for storage integrity. Capture the document and its identity together across asynchronous work. [History entry and selection](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/main/java/com/greenezone/gzphotoeditor/editor/ProModel.kt#L52-L82) · [Android AtomicFile contract](https://developer.android.com/reference/android/util/AtomicFile)

**Closure.** Run the two-name sequence through the existing dialogs. Restart the activity or app, reopen both names through File, and verify their layer names, order and distinguishing pixels. Follow with Undo across Open, Redo, Save As to an unused name, deliberate collision and Cancel, including two inputs that canonicalize to the same key. Keep the existing single-name reset/Undo and named-delete Cancel/Confirm checks green. Use disposable projects throughout. [Existing tests](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/androidTest/java/com/greenezone/gzphotoeditor/ProWorkingDocumentTest.kt#L131-L225)

## PRO-05 · A successful write can produce an unreadable Pro project

The current drawing model admits 160 strokes with 500 points per stroke. The inner encoder serializes the coordinates as decimal float pairs separated by commas and semicolons. It places no whole-string length check on its return. Its decoder rejects a recipe longer than 2,000,000 characters. The Pro wrapper accepts up to 3,000,000 UTF-8 bytes per encoded document. A save can therefore pass outer validation and replace the file even though its current layer recipe cannot be decoded. The project list reads filenames, so it can continue to show the unreadable name. [Model validation](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/main/java/com/greenezone/gzphotoeditor/editor/ProModel.kt#L100-L116) · [Stroke count limit](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/main/java/com/greenezone/gzphotoeditor/editor/CreativeRaster.kt#L16-L22) · [Inner format](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/main/java/com/greenezone/gzphotoeditor/editor/EditDocumentCodec.kt#L108-L128) · [Outer writer and layer reader](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/main/java/com/greenezone/gzphotoeditor/editor/ProStore.kt#L74-L115)

**Counterexample.** Use a single visible drawing layer, a neutral grade and empty or equal reset baseline on a runner with at least a 48 MiB Java heap. Build 160 strokes of 500 samples each, alternating the points `(0.00012345678f, 0.00045678912f)` and its transpose. All coordinates are in [0,1]. Each coordinate's JVM string representation has 12 ASCII characters. With a comma in each pair and 499 semicolons per stroke, the values alone occupy **2,079,840 characters**. The fields and JSON wrapping of this one neutral layer fit within the remaining approximately 920 kB of the outer cap. This is a deliberately dense model-level boundary case. We did not observe an owner creating that project by hand. [Host control](../proofs/ProBoundaryControls.java) · [Recorded output](../evidence/ProBoundaryControls.txt)

**Read failure and baseline nuance.** With a null or equal reset baseline, the writer stores the document directly. An explicitly empty baseline adds a small marker. A different nonempty baseline is separately encoded and wrapped, subject to a total cap of 6,000,512 bytes and a runtime-heap bound. On load, an oversized primary layer causes the whole current document to decode to null before optional-baseline recovery runs. An unreadable *optional* reset with an otherwise readable current document falls back to the current document, which also changes subsequent Reset behavior. Passing a size check or successfully syncing bytes is insufficient to guarantee round-trip readability. [Project wrapper and fallback](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/main/java/com/greenezone/gzphotoeditor/editor/ProStore.kt#L185-L218) · [Save, list and reload](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/main/java/com/greenezone/gzphotoeditor/editor/ProStore.kt#L228-L292)

**Repair choices.** Define one bounded contract for what the nested format can write and read. Preserve the previous healthy save if the new document cannot be encoded readably. An initial fix can reject over-budget recipes before `startWrite`, retain the working draft and show a specific actionable message. Supporting the model's full admitted range may justify a compact, backward-readable format later. Check existing oversized saves for bounded recovery where the older bytes contain complete data. A blanket increase of the allocation ceiling needs testing on small heaps. The same codec is used by other workspaces, so qualify those callers before changing its contract.

**Regression with a negative control.** A [proposed Android instrumentation case](../proofs/ProStoreRoundTripInstrumented.kt.example) exercises the production writer and reader in one disposable namespace. The audit verified its API references and did not run it on Android. First save a small healthy A. Build the large document above in the same instrumentation package as the existing atomic-store tests. Record the length of `EditDocumentCodec.encode(layer.edits)`, its UTF-8 byte length, and the length of `ProStore.encode(document)`. Assert the document is model-valid. Attempt replacement under the same name on the pinned build and log the write result and subsequent reload. On a repaired build, a reported successful save must cold-reopen the exact layer/stroke/point counts and reset baseline. A rejected save must leave A's former bytes, decoded document and working draft intact. Include a separate large-reset/short-current case. Probe exact-limit, one-over, and previous codec versions. Preserve all results, including an unexpected rejection on a device with a smaller heap. [Prior atomic-file tests](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/androidTest/java/com/greenezone/gzphotoeditor/AndroidProAtomicStoreTest.kt#L15-L52)

## PRO-03 · Panorama import misaligns canvas geometry and hit targets

Pro's own image picker decodes a thumbnail with a maximum edge of 200 px, calculates its aspect, then clamps it to [0.1,10]. The renderer fits the real decoded bitmap. The selection guide, hit testing, retouch target and mask anchor use the stored layer aspect. Pro's current model accepts a much wider range. The existing wide-aspect regression constructs a layer with the correct aspect in code, bypassing the picker. [Import handler](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/main/java/com/greenezone/gzphotoeditor/ui/ProWorkspaceScreen.kt#L414-L430) · [Rendered bounds](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/main/java/com/greenezone/gzphotoeditor/editor/ProRaster.kt#L267-L290) · [Guide and inverse mapping](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/main/java/com/greenezone/gzphotoeditor/editor/ProModel.kt#L148-L200) · [Existing aspect test](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/androidTest/java/com/greenezone/gzphotoeditor/ProAspectRatioTest.kt#L23-L54)

**Discriminating observation.** Add the field guide's 4,000 × 100 panorama through Pro on a square canvas. At a normalized 1,000 × 1,000 canvas, a centered 40:1 image occupies 25 px in height. A 10:1 guide occupies 100 px. A long press at normalized (0.5, 0.53) is on blank canvas but falls within the stored bounds. Put an opaque lower photo beneath the panorama. That same press can select the panorama rather than the visible lower image. Inside the narrow image, a vertical retouch offset will map to the wrong source row. Scaling a provisional raster can introduce small rounding differences. It cannot explain a fourfold disagreement. [Picking](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/main/java/com/greenezone/gzphotoeditor/editor/ProHitMath.kt#L13-L34) · [Retouch binding](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/main/java/com/greenezone/gzphotoeditor/ui/ProWorkspaceScreen.kt#L774-L800)

**Repair and proof.** Use the oriented source dimensions as the new layer's geometric authority. `ImageDecoder.ImageInfo.getSize()` exposes dimensions before requested downscaling. Check orientation explicitly with a rotated fixture. Use one fitted image frame for render, guide, mask, picking and inverse retouch mapping. For old projects, preserve existing mask anchors and saved edits. Recover better dimensions for readable source URIs with a compatibility test, and retain a meaningful fallback if permissions have expired. Exercise 40:1 and 1:40 through actual add-image and replacement handlers. Sample guide edges and rendered bounds, then place a known clone mark, save, cold-reopen, and inspect a PNG. The center alone cannot catch this failure. [Android ImageInfo](https://developer.android.com/reference/android/graphics/ImageDecoder.ImageInfo) · [Existing decoder scaling](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/main/java/com/greenezone/gzphotoeditor/editor/ImagePipeline.kt#L60-L78)

## PRO-04 · “Original dimensions” can enlarge a small source

The shared dialog promises original edited image dimensions. A Regular-to-Pro handoff stores the edited aspect but has no canvas pixel width or height. Pro export chooses a 4,096 px maximum edge and scales for a memory-class budget. The ORIGINAL layout returns that generated bitmap unchanged. Small images can be enlarged, and large images reduced. The size and text disagree in particular for a handoff that already has a known edited pixel extent. For a blank multi-layer project the user also needs a concrete declared canvas size. [Export dialog](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/main/java/com/greenezone/gzphotoeditor/ui/EditorDialogs.kt#L81-L106) · [Handoff recipe](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/main/java/com/greenezone/gzphotoeditor/ui/PhotoEditorScreen.kt#L349-L380) · [Pro export](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/main/java/com/greenezone/gzphotoeditor/ui/ProWorkspaceScreen.kt#L497-L526) · [Original layout](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/main/java/com/greenezone/gzphotoeditor/editor/ImageExportWriter.kt#L14-L22)

**Example and implementation.** A 120 × 80 source cropped to 80 × 80 and passed to Pro is a useful starting point because the existing test already makes that transfer. At a 128 MiB memory class the budget is 3,355,443 pixels. With the current formula the square output is 1,831 × 1,831. That is a calculated result for that memory class, not an observed handset file. Define the project canvas's intended pixel dimensions explicitly and preserve them across save/reopen. Take handoff geometry from full-resolution source metadata and the committed recipe. A proxy is allowed for drawing. If an Original export would exceed memory or product limits, offer a specific size or a tiled render and show the actual dimensions before Save. Use a stable legacy fallback for files with only an aspect. [Pixel budget](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/main/java/com/greenezone/gzphotoeditor/editor/ImagePipeline.kt#L45-L49) · [Size calculation](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/main/java/com/greenezone/gzphotoeditor/editor/ProModel.kt#L134-L146)

**Closure.** Through File → Export image, choose Original and PNG for the 80 × 80 handoff. Decode the actual file independently, compare the PNG width/height and the same 16 positions used in the transfer test, then reopen the Pro project and repeat. Check an unchanged small portrait, a source above budget, one aspect-change operation, a blank project and a fixed social preset. Confirm the filename, previewed output dimensions and file header agree.

## PRO-02 · Continuous brush and eraser truncate a stroke

Point capture stops once the current stroke has 500 points. Release commits the accumulated prefix. Repeating the gesture with the eraser has the same limit. The model and inner recipe both enforce 500, so a UI-only increase would create files that fail validation or lose the tail on reload. The drawing layer also stops accepting new strokes at its maximum, requiring explicit feedback if the edit cannot be represented. [Gesture capture and commit](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/main/java/com/greenezone/gzphotoeditor/ui/ProWorkspaceScreen.kt#L805-L813) · [Point cutoff](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/main/java/com/greenezone/gzphotoeditor/ui/ProWorkspaceScreen.kt#L837-L869) · [Recipe encode and decode](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/main/java/com/greenezone/gzphotoeditor/editor/EditDocumentCodec.kt#L108-L125)

**Repair choices.** A bounded, geometry-preserving simplifier can keep the complete path including its newest endpoint. Another option is a group of bounded segments representing one gesture in history. With segmentation, a shared join on a semitransparent stroke can increase alpha if painted twice. Test the joins, stroke budget, save limits and atomic cancellation. Do not weaken the lower-layer compositing that now works. Existing two-pointer cancel switches to viewport navigation. A short tap already toggles the controls, as requested by the owner. [Pointer routing](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/main/java/com/greenezone/gzphotoeditor/ui/ProCanvasSurface.kt#L98-L148) · [Current paint regressions](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/androidTest/java/com/greenezone/gzphotoeditor/ProCanvasInteractionTest.kt#L93-L203)

**Closure.** Drive a single continuous drag with at least 800 delivered distinct points, with a bend and unique endpoint wholly after point 500. Verify the tail during touch, after release, after project reopen and in exported pixels. Repeat with erasing an existing opaque path, an occluding upper photo, and a 50%-opacity stroke crossing a segmentation join. One Undo must remove the entire gesture. Pinch cancel must leave history and pixels intact. Record how many input samples actually reached the app, since injected events may be coalesced.

## Preserve working behavior and measure the remaining risk

- The merged tests distinguish real pixels during a held lower-layer brush and eraser, check an upper image's occlusion, preserve unaffected ink and require zero alpha in the fully erased interior. They demonstrate those fixtures. Continuous display pacing, long strokes and UI-based layered reopen-to-PNG are separate observations. The #229 alpha failure sampled a partially covered pixel, and the corrected 512 px fixture retained the zero-alpha assertion. [Raw earlier failure](https://github.com/MrSkyrimFan/GZ-Mobile-001/actions/runs/45119141835/artifacts/14793267536) · [Test correction](https://github.com/MrSkyrimFan/GZ-Mobile-001/commit/34ec0b9459c3b1f9f4c1859e169cec6983944018)
- Preserve the selected layer through reorder and Undo/Redo, the correct reset baseline through Open/Undo, named-delete confirmation, the separate active working document, missing-media ownership, legacy text rendering and backward file compatibility. Existing tests supply specific examples for all of these. [Ownership tests](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/androidTest/java/com/greenezone/gzphotoeditor/ProToolOwnershipTest.kt#L97-L149) · [Legacy text reopen](https://github.com/MrSkyrimFan/GZ-Mobile-001/blob/14df73926c6f7063a488f84e367268168e8e5444/app/src/androidTest/java/com/greenezone/gzphotoeditor/ProWorkingDocumentTest.kt#L253-L302)
- The named Pro store performs synchronous JSON serialization and AtomicFile I/O directly from the Save callback, and synchronous loading when an Open button is pressed. This is a responsiveness risk. No handset ANR or pause duration is claimed. While correcting project save, measure a high-content save/open with frame timing and main-thread disk detection. Keep the user-visible state, target and success message consistent if moving writes to a worker. Project identity is a small piece of state suitable for restoration. Large recipes and bitmap buffers belong in a durable project/draft store.
