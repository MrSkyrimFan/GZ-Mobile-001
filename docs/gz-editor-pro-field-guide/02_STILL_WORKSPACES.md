# Three still-image workspaces that feel like one app

**Design brief for Codex.** Imagine someone using their right thumb to crop a family photo, blur an address, add a caption and send it. Now imagine a photographer developing a DNG or a compositor painting through a foreground layer to reveal an object behind it. All three should be able to trust their eyes, undo their last decision, leave and find their work again. Their tools belong to the document they are editing. The examples below describe intended behavior and useful experiments. The baseline chapter records which experiments already have evidence. A future capability in this chapter is a product target.

## Who owns the next tap?

| The person's intent | Workspace and editable object | What crosses the boundary |
|---|---|---|
| “Fix my photo, style it, cover an address, put a caption or sticker on it.” | Regular. One source photograph with an editable recipe and simple decorations. Advanced photographic development, camera profiles, optics, catalog and batch also live here. | A saved rendition can become a Pro image layer or Collage tile. The Regular project keeps the decisions behind that rendition. |
| “Build an image from pieces. Change this subject, replace the background, paint through one layer.” | Pro. A document with independently addressable layers, selections, masks, paint, shapes, local transforms and effects. | A saved composite can start another Regular edit. A named Pro project retains layers, masks and editable geometry. |
| “Arrange these photos in a layout, then fix only the third tile.” | Collage. A layout of up to 20 separately editable tile instances. Its embedded photo tools target the selected tile. | An export is one composition. The native collage retains its layout and all tile edits. |
| “Put a photo look on a clip or animated image.” | Video or GIF. A time range, clip or frame group owns the look. | Share tested color math or profile definitions. Each workspace presents its own scope, playback and export. |

Regular owns Text authoring, Blur & cover and the planned Stickers menu. Masks authoring and the visible Masks setting belong in Pro. A Regular or embedded Collage file saved by an older build may contain a mask. Its appearance and serialized data must survive an unrelated edit. A legacy Pro text layer must render, transform and round-trip where the existing project supports it. New caption authoring remains in Regular. Older blueprints assigning masks to Regular or a new Type tool to Pro conflict with these later owner decisions.

### One integration test worth keeping forever

Use an asymmetric photo with distinct corner marks, a near-center fine line and orientation metadata. In Regular apply an off-center crop, a noticeable Look and a small caption. Capture the intended crop in source-pixel coordinates. Choose Pro and answer **Yes** to continue with this edit. Check the delivered extent, orientation, corner marks, caption placement and color at multiple locations against an independent Regular render. Repeated transfer must apply each operation once. With **No**, preserve the reported existing empty/select-image flow and the Regular project. Cancel the selection and return. Compare the Regular revision, visible edit and next Undo result. Also exercise a pre-existing Pro draft so opening, retaining, replacing or discarding a document always follows an explicit user choice when work could be lost.

Continue the long route. Save a named layered Pro project, export its finished appearance, open that image in Regular, apply a second grade and save a new version. Reopen the original Pro project and move a layer. The two saved versions should still have the intended independent appearances. Rotate the device, cancel a picker and return after process recreation at different points. An implementation can use a lossless rendered intermediate, an immutable revision reference or another recoverable representation. Compare alpha, dimensions, orientation and color profile at the boundary. Importing a rendered result does not confer sensor data or recoverable highlight information. Keep source files intact throughout.

## Regular photo editing

### The first minute

An unaided first-time editor can pick an image, compare a Look, crop it, add text and find the saved image. Use the existing canvas, tool placements, appearance and hide/show behavior. A photograph fills the useful area while its controls stay findable. A user who opens advanced Light or Color options should be able to get back to the photo with the same framing. Returning from the keyboard keeps a caption draft. Applying it creates one editable caption in the expected position. Back dismisses the innermost active interaction and returns to the preceding work. Observe an unfamiliar user completing the sequence with one hand. Record *which control they touched and what they expected* if it fails.

| User action | Implementation concern to test | What someone can see in the result |
|---|---|---|
| Grab a crop edge, corner or interior | Compute hit regions in displayed screen coordinates with density-aware extents, resolve overlaps against actual pointer-down position, then map movement through the image transform. Assign the chosen target for the entire drag. Tiny frames need a meaningful center and edge midpoints even with overlapping hit areas. | A thumb placed near a corner can resize on its first continuous gesture. The middle of an edge controls that edge. Dragging the center translates the frame. The toolbar, letterbox and system gesture insets do not consume reachable handles. |
| Lock a crop ratio, rotate, commit and export | Solve the selected ratio inside oriented source-pixel bounds. Use one rounding rule at export. A visual minimum touch region can extend beyond a small on-screen frame without expanding the source-pixel selection. | On the known 4,000 × 100 panorama a full-height square is 100 × 100 after export and reopen. Check the edge landmarks too. Repeat with a portrait panorama, an odd-pixel source, freeform and two non-square locks. |
| Add text and edit it a second time | Preserve text, newline, alignment, font/fallback, size, color, position, scale and rotation as applicable. Use the same content bounds in preview and export. One user gesture should be one Undo step. | Enter two lines including an accented letter, dismiss the keyboard, drag and resize the caption, undo/redo, reopen and export. Its line breaks and anchor survive. Unrelated photo edits leave the caption intact. |
| Paint Blur & cover with the tool panel hidden | Interpolate sampled pointer positions along a stroke. Express brush width consistently under zoom. Apply the stroke to the oriented/cropped image at the chosen radius. Clip soft edges and isolate each effect. | A continuous swipe over a checkerboard visibly reduces local contrast while the finger moves. Nearby untreated features stay sharp. Undo removes just that stroke. An opaque cover fully covers an interior test patch through export. Label the distinct effects clearly. |
| Choose B&W, Punch or neutral and then tune exposure | Track the look and independent adjustments under the app's documented composition rules. Render preview at interactive resolution, then export the same settings at source resolution. Version changed look definitions so old projects remain reproducible. | A neutral export preserves intended colors within the chosen format's tolerance. B&W gives neutral gray on colored patches. Changing exposure preserves crop, privacy strokes, text and stickers. Undo restores the prior appearance. |
| Inspect RGB histogram and clipping in an advanced photo control | State which pixels and which stage are measured, how alpha-zero pixels are treated, whether bins are estimated from a proxy, and which color encoding and thresholds define clipping. Keep clipping warnings and bin calculation consistent. Coalesce rapid updates so the final drag result wins. | Use known black, white, gray and saturated red patches. Move exposure and check the appropriate channel end bins and overlay location. Return to neutral. The overlay is a viewing aid and never appears in the exported pixels. |

Android recommends a 48 dp minimum target for interactive controls and documents how Compose can expand a touch target outside a small component. A custom crop canvas still needs its own hit resolution. Simply giving eight nearby handles equally large circles can make the wrong handle win on every touch. A useful experiment is to log which handle wins across a grid of points around a 40 dp frame and inspect five actual finger drags on the smallest supported handset. ### The photographer's path inside Regular

| Capability | Product behavior and engineering choices | Evidence before advertising support |
|---|---|---|
| Source interpretation and high precision | Track encoded JPEG/PNG, rendered RGB and supported RAW separately. For mosaic RAW, honor supported orientation, active area, black/white levels, calibration and white balance. Choose and document a demosaic and processing order, internal precision and fallback for unsupported variants. Preserve highlight headroom until the intended tone mapping. | Test licensed camera samples and independently interpretable synthetic data, including a clipped channel, neutral ramp and two color patches. Compare against a known reference at declared stages. Publish a tested camera/format matrix. Rendering the JPEG preview inside a DNG proves only thumbnail access. |
| Tone, color and optics | Offer exposure, white balance, selective hue/saturation/luminance, curves, tonal grading, detail/noise controls, lens distortion, chromatic aberration, vignette and perspective corrections as depth within Regular. Clearly separate sensor interpretation, the creative look, the working space, display conversion and output encoding. | A neutral ramp stays ordered after the neutral path. A distortion grid straightens with the correct profile. A two-color edge exposes channel misregistration. Profile choices change the intended output and the output carries the matching profile. |
| Color management and export | Respect source profiles where supported. Tag output with the space actually encoded. Define a sensible untagged-input policy and source capability fallback. Use lossless references for pixel-exact tests and declared tolerances for lossy encodings. Inspect wide-gamut content on a device with the relevant display capability when qualifying that claim. | Decode exported assets independently and convert both actual and reference into one comparison space. Check alpha edges, out-of-gamut colors and a smooth gradient. Check a conventional sRGB viewer as well as the managed phone preview. |
| Local catalog and batch | Provide ratings, collections, search, virtual versions and selective recipe copy. Freeze each batch item's source revision, recipe, destination and naming decision. Stage complete files and track per-item commit state. Make failed and canceled jobs recoverable, including permission loss at a document provider. | With multiple inputs, apply exposure only and verify that individual crops survive. Revoke one grant and interrupt a batch after one committed output. On retry, keep prior successful files, resume the recoverable item, identify the unavailable one and preserve all originals. |
| Later professional depth | Qualify supported HDR bracket merging, panorama stitching and focus stacking separately when included. Keep source provenance, alignment and a recoverable result. Architect for growth without presenting empty controls. | A moving subject in bracketed exposures, a repetitive fence in a panorama and a focus boundary in a macro set all reveal different defects. Show seams, ghosts, alignment and retained fine detail on actual full-resolution output. |

These families describe desired professional workflows. A camera profile and a creative filter solve different problems, and a successful sRGB photo says little about RAW calibration. Platform and industry references provide concrete comparison material. ### Stickers, after the active repair work

The catalogue in Revision 3.1 proposes **648 designs across 27 categories**. It is a design inventory. Production status needs an actual asset, stable ID, provenance/rights record, thumbnails, intended size range and a successful on-device/export inspection. Hearts, flirty and sad hearts, stars, rainbows, apples and bananas give a concrete small pack to qualify end to end. Extend the qualified workflow across the rest without multiplying menus in the editor.

The dedicated Regular Stickers menu can expose categories and a quick way to find an item. In one sequence, place the same sticker twice, drag one, rotate/scale the other, change their stacking where supported, delete one, Undo, save, restart, reopen and export. A sticker placed at the crop edge clips cleanly. Transparent corners must remain transparent. Inspect a light, dark and textured background at small and large scales for fringes, blurry outlines or accidental opaque rectangles. Check first open offline and memory while scrolling a populated catalog. Retiring or reordering a pack should leave older images readable through stable IDs and available assets. Asset format, original production method, packing and caching are engineering choices. Asset production is distinct from adding runtime AI to the editor.

## Pro image construction

### The painting defect is visible before the finger lifts

Build a fixture with an opaque patterned lower layer, an upper layer with both transparent and opaque regions, and a partially masked or transformed layer. Select the **lower layer**, choose a high-contrast brush, hide controls and press down. Move across all three regions and **hold the pointer down while capturing the actual canvas**. An opaque upper region occludes the stroke. A transparent region exposes it. A partially covered region blends it. On release, the stroke stays at the same place with the same color and coverage within the declared preview tolerance.

Next select the paint layer between the two media layers and erase part of the committed stroke. In the uncovered area the lower pattern appears during the drag. The top image continues to cover the paint where it is opaque. Save with alpha, reopen the layered project and export PNG. Compare interior and boundary patches in the held-down, committed, reopened and exported images. Undo removes one stroke; Redo restores it. Repeat after panning, zooming, rotating or flipping a layer, selecting another layer and hiding the toolbar. Use matching coordinate transforms for both pointer and renderer. Inspect initial contact, sustained movement and the transition at lift separately. An end-of-stroke screenshot misses the original defect.

A viable implementation can compose a temporary stroke into the target layer, then composite the visible stack, invalidating only affected tiles. A hardware-accelerated brush surface can meet the same behavior. Each preview result needs a document revision, layer identity, stroke ownership and viewport identity. A canceled or superseded render can release its own resources without replacing the currently visible work. Bound tile/cache memory against representative high-resolution photos and preserve authoritative source edits when evicting preview tiles. Time the path from input delivery to visible change at a documented display refresh rate. Show first stroke on a cold image, repeated strokes on a warm image and one sustained stroke through several overlapping layers.

### Building the Photoshop/GIMP-class workflow in coherent slices

| Capability | A useful vertical slice | Acceptance that distinguishes a real tool |
|---|---|---|
| Layers, groups, transforms and blending | Add two source images, duplicate, reorder, lock, set opacity/blend, align, transform, group, save and reopen. Bind selection, masks and operations to stable layer identity through reorder/Undo. Distinguish transforming content, resizing the canvas and cropping the composite. | Undo reorder, then immediately paint. The originally selected layer receives it. Under a 50%-opaque isolated group, overlapping opaque children have 50% group coverage. Check Screen over a midtone and over white. A white result over white can be mathematically correct. |
| Selection and mask authoring | Build rectangular/ellipse/freehand and color range selections, then add/subtract/intersect, feather, invert, convert to an editable visibility mask, link/unlink to layer motion and refine edges. Use separate concepts for selection, layer coverage and the editable mask target. | Move a layer and its linked matte together, then unlink and move the layer alone. Check fractional edge coverage against a known matte. A missing or replaced layer cannot redirect an unfinished mask to its neighbor. Save and reopen both linked and unlinked cases. |
| Subject and background | Select a subject, keep/remove areas, refine against light and dark backdrops. Offer transparent, solid and replacement-photo backgrounds with independent transforms. Preserve a reversible mask. Manual brush, paths, color range or conventional edge methods can deliver this offline. | Use a subject with a hole and a fine edge crossing a contrasting background. The hole stays open, foreground colors stay clean at the boundary and replacement content keeps its own geometry. A transparent PNG opened over a checkerboard reveals actual alpha. |
| Retouch, reshape and retexturing | A clone tool needs a sample point, target, brush shape and clear aligned/unaligned behavior. Healing needs a clear source and destination and a texture/lighting strategy. Manual mesh deformation or Liquify-style push/pull, freeze and reconstruct supports local reshaping. A replacement texture needs warp, a matte and control over preserved shading/detail. | Remove one object on a textured background and inspect repetition and seams at 100%. Reshape a garment beside a straight wall using a protected region. The wall stays straight. Reconstruct one changed area, undo the operation and save/reopen. Recolor/retexture only the selected fabric and keep folds visible. |
| Drawing, shapes and effects | Support brush size, softness, opacity and flow. Add qualified pressure/tilt behavior with a finger fallback. Keep editable shapes, effect parameters, ordered filters and independent clearing/disable. Keep legacy text renderable. Adjustment controls may target a specific layer/effect in Pro. | Brush across the viewport at two zooms and export. The footprint matches its declared units. Clear one effect, leaving mask, grade and other effects intact. A shape remains editable after reopen. Hidden/locked layers follow their visible states for edits and export. |
| Document, save and reset | Keep per-document source/reset baseline, selected layer and history consistent through New, Open, Undo, Redo and restore. Keep an unapplied tool draft scoped to its target. File → Delete current work resets the active session after confirmation. Deletion of a named save is a separate confirmed action. | Open B while editing A. Undo. Reset A and confirm its documented starting state. Reopen B and both originals. Cancel a named deletion and verify bytes. Confirm deletion of B's save and verify the active work and unrelated saved projects. Simulate interrupted writes and an absent source. |

For compositing tests, compare independently calculated patches in the renderer's declared working space. For normal source-over with premultiplied RGB, output premultiplied color is source premultiplied color plus backdrop premultiplied color multiplied by one minus source alpha. The same coverage rule applies to output alpha. Different blend operators add their own specified color step. For erasure, reducing the target layer's premultiplied color and alpha together lets lower layers show through without a dark fringe. Declare whether a readback is encoded or linear, premultiplied or straight, before comparing actual numbers. ## Collage as a protected 20-photo workspace

The user has already chosen this workflow. Preserve its independent entry, existing layout and normal tile editor. Verify it when shared photo rendering, crop math, navigation, import or project serialization changes. Full Collage control means the user can choose a layout and aspect, arrange, add, remove, replace or reframe individual tiles, adjust fit/fill and alignment where applicable, style margins/gutters/borders/corners/background, choose output dimensions and save an editable project. Check which of these already ship before implementing gaps. Keep the current capability vocabulary and placement wherever it works.

Use a twenty-tile fixture with visible numbers, edge chevrons and distinct center colors. Populate two tiles from the **same source** and give them different crops. The tile instance owns identity, independent of current slot and source URI. Edit tile 7, cancel, and compare all twenty recorded edits. Repeat and commit once. Reorder it and apply a second change. If a picker returns after reorder, replacement should still reach the initiating tile or be safely canceled if that instance was deleted. A failed source permission should name the affected tile and preserve the other nineteen. Render the first nineteen while waiting or preserve the editable document with recoverable missing media, according to the normal product behavior.

Switch layout and aspect. Layout changes can move neighboring tiles legitimately. Verify that each tile's *own edit and identity* survives and compare the new expected placement against an independent layout map. For a pure single-tile edit in an unchanged layout, compare all nineteen neighboring outputs. Check preview and independently decoded full-size output, including gutter/border samples, corner coverage and intended fit/fill crop. Reopen the project and repeat after process recreation. Repeat with one tile, two tiles, twenty and an attempted twenty-first. Keep existing contents usable at the limit. Delay a provider read, cancel a destination picker and interrupt an export. Preserve the last valid named project and avoid reporting success for a partial output.

## Practical handoff for these three editors

A concise still-image repair receipt can fit on one screen: project/build identity, starting image or project revision, exact gesture or menu action, preview seen during the action, result after release, Undo result, independently read saved output, handset conditions and any remaining reproducible defect. Include a pointer-down capture for brush/eraser and an actual drag trace for crop. For unit tests, retain one deliberately discriminating fixture per behavior. An asymmetric test image prevents a flip bug from looking correct. A top layer with a transparent hole makes painting on the wrong layer obvious. Two tiles using the same photo catch identity bugs that twenty different filenames cannot.

Engineering is free to move work out of the UI thread, change internal architecture, replace an algorithm, share a renderer or build a new local component when that improves these outcomes. The reason for a change should survive a simple question: **which person's action failed, and what now proves they can finish it?**
