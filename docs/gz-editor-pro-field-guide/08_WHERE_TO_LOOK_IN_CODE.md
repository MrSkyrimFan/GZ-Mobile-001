# Where the design touches the current code

These are starting points from the actual PR diffs. File names refer to the Android `app/src` tree in `MrSkyrimFan/GZ-Mobile-001`. They help locate an experiment without dictating where the eventual repair must live. Look up the call chain at the current head before editing. The source on main and an unmerged photo branch can legitimately differ.

| Question | First place to inspect | Experiment that distinguishes causes |
|---|---|---|
| Why does Save take longer than playback? | In #20, `editor/VideoGifSource.kt`, `editor/EditedVideoPreviewReader.kt` and `ui/VideoGifScreen.kt` changed with `AndroidVideoGifDecodeTest.kt` and `AndroidGifWorkspacePlaybackTest.kt`. | Record request times, sync seeks, decoded/presented frames, staging completion and final provider close. Compare sequential/compatibility paths on the same short source. If decode time falls while total Save time holds, inspect palette/compression/storage before changing decoder strategy again. |
| Why does an edited preview seem to freeze? | Follow the UI gesture in `VideoGifScreen.kt` into the playback state, frame selection, current reader and visible image update. Inspect the actual latest revision of the reader. | If requests continue but presented frame identity remains constant, examine frame selection/cache/render. If the clock stops issuing work, inspect intended pause/resume and ownership after the gesture. If frames are correct but arrive slowly, trace wait time, queueing and conversion. A continuous export path shares some infrastructure but cannot establish interactive pacing by itself. |
| Does the histogram describe the same image the person sees? | In #21, `editor/PhotoHistogram.kt`, `ui/PhotoHistogramDialog.kt`, `ui/PhotoEditorScreen.kt` and `ui/EditorDock.kt` connect calculation, the presented image and the entry in More. | Measure the unmodified reference image, the rendered edited preview and Before on the same scene. A wrong bin on the known source points toward counting or pixel representation. A correct isolated count with the wrong Before/Edited response points toward publication, image choice or stale calculation. |
| Does the paint preview respect the full layer stack? | In #21, follow gesture routing in `ui/ProCanvasSurface.kt`, draft ownership in `ui/ProWorkspaceScreen.kt`, and drawing/composition through `editor/ProModel.kt` and `editor/ProRaster.kt`. The held-gesture test is in `ProCanvasInteractionTest.kt`. | Inspect held vs committed output on both covered and exposed pixels; verify transparent export after erasing. If persisted pixels are already correct and only held pixels disagree, inspect draft compositing. If both disagree, inspect layer transform, mask and compositing space before changing the overlay. |
| Does a difficult crop come from picking or from export math? | Inspect `editor/CropMath.kt`, the crop overlay's pointer-down handler and the final source-pixel crop. Preserve the #19 regressions. | A wrong target on touch-down is a picking problem. A correctly moving rectangle with a wrong decoded aspect after export is a source-coordinate/rounding problem. Test the two independently, then together with rotation and the normal entry path from Regular. |
| Why did an unrelated tile or layer change? | Follow the selected object's identity from navigation into the callback, document mutation, history, save format, renderer and reopen path. In Collage start at the workspace, collage model/store and raster code. | Use two independently edited instances of the same URI. Reorder them before a delayed result returns. If the mutation follows slot or URI instead of instance, fix the first boundary that loses identity and exercise the subsequent export. |

When faced with an unfamiliar tool, a trace that follows one action is often faster than a broad inventory. Read the selected input, its coordinate or time transform, the editable value it changes, the point that commits it to history, the preview calculation, the project serializer and the final renderer. The first boundary where a known expected value becomes wrong is usually the cheapest place to run the next experiment. A local cause merits a local repair; a shared broken invariant merits a shared repair with checks on its actual consumers. Preserve a failing example when that will prevent the same regression.
